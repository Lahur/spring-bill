Before the app pod will come up healthy, seed Vault (kv-v2 at "secret/spring-bill",
the default path Spring Cloud Vault looks up for spring.application.name=spring-bill).
Postgres and Vault are provisioned separately by k8s_pulumi/pulumi_hetzner in this
same namespace ("postgres"/"vault" Services) - make sure that stack has been
applied before installing this chart.

  kubectl -n {{ .Release.Namespace }} get secret postgres -o jsonpath='{.data.POSTGRES_PASSWORD}' | base64 -d
  kubectl -n {{ .Release.Namespace }} exec -it deploy/{{ .Values.vault.serviceName }} -- sh
  export VAULT_ADDR=http://127.0.0.1:8200
  export VAULT_TOKEN={{ .Values.vault.token }}

  vault kv put secret/spring-bill \
    spring.datasource.url="jdbc:postgresql://postgres:5432/spring_bill" \
    spring.datasource.username="postgres" \
    spring.datasource.password="<value from the kubectl command above>" \
    spring.security.oauth2.resourceserver.jwt.issuer-uri="https://<keycloak-host>/realms/<realm-name>"

(Add/replace keys to match whatever spring.* properties the app actually
needs at runtime - these are not otherwise defined anywhere in the jar for the
"prod" profile, they only come from Vault. The issuer-uri must point at a
Keycloak realm exposing /.well-known/openid-configuration; no Keycloak client
library is needed, Spring's standard oauth2-resource-server support handles
any OIDC-compliant issuer.)

Also confirm the k3s node(s) can pull from the plain-HTTP registry - if this
hasn't been done yet, add to /etc/rancher/k3s/registries.yaml on each node and
restart k3s:

  mirrors:
    "docker-registry.registry.svc.cluster.local:5000":
      endpoint:
        - "http://docker-registry.registry.svc.cluster.local:5000"
  configs:
    "docker-registry.registry.svc.cluster.local:5000":
      tls:
        insecure_skip_verify: true
