spring-bill deployed to namespace {{ .Release.Namespace }}.

App reachable at: http://<any-k3s-node-ip>:{{ .Values.service.nodePort }}

Before the app pod will come up healthy, seed Vault (kv-v2 at "secret/spring-bill",
the default path Spring Cloud Vault looks up for spring.application.name=spring-bill).
Vault itself is deployed separately via the helm/vault chart - install that first
if it isn't already running in this namespace:

  kubectl -n {{ .Release.Namespace }} exec -it deploy/{{ .Values.vault.serviceName }} -- sh
  export VAULT_ADDR=http://127.0.0.1:8200
  export VAULT_TOKEN={{ .Values.vault.token }}

  vault kv put secret/spring-bill \
    spring.datasource.url="jdbc:postgresql://{{ .Release.Name }}-postgres:5432/{{ .Values.postgres.db }}" \
    spring.datasource.username="{{ .Values.postgres.user }}" \
    spring.datasource.password="{{ .Values.postgres.password }}" \
    okta.oauth2.issuer="<your-okta-issuer>" \
    okta.oauth2.client-id="<your-okta-client-id>" \
    okta.oauth2.client-secret="<your-okta-client-secret>"

(Add/replace keys to match whatever spring.*/okta.* properties the app actually
needs at runtime - these are not otherwise defined anywhere in the jar for the
"prod" profile, they only come from Vault.)

Also confirm the k3s node(s) can pull from the plain-HTTP registry - if this
hasn't been done yet, add to /etc/rancher/k3s/registries.yaml on each node and
restart k3s:

  mirrors:
    "docker-registry.registry.svc.cluster.local:5000":
      endpoint:
        - "http://docker-registry.registry.svc.cluster.local:5000"
  configs:
    "docker-registry.registry.svc.cluster.local:5000":
      tls:
        insecure_skip_verify: true
